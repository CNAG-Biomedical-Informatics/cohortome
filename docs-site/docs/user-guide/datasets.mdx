The `Datasets` tab defines the active workspace.

:::note
This tab is user-facing. It is different from `Data Administration`, which controls dataset policy.
:::

## What the tab does

This tab is where a user chooses which authorized datasets should be active at the same time.

The result is the current workspace used by:

- `Dashboard`
- `Query`
- `Analysis`
- `Pheno-Ranker`

![Datasets tab with active and pending workspace state](/img/screenshots/datasets-tab.png)

## Active vs pending selection

The dataset picker distinguishes two states:

- `Active`
  - currently applied to the workspace
- `Pending`
  - selected in the picker but not yet applied

The workspace does not change immediately when a checkbox changes. It changes only when the user clicks:

- `Apply workspace`

The previous active workspace remains usable until the new workspace is applied.
This matters when a large dataset is selected: the user can still see the
current default workspace while the pending selection is only a proposal.

:::warning Pending is not active
If you check or uncheck datasets but do not click `Apply workspace`, the backend is still operating on the previous active workspace.
:::

## Default versus on-demand datasets

Current startup behavior is intentionally simple:

- `default-dataset` loads at application launch
- every other dataset is on demand
- on-demand datasets are loaded only after the user clicks `Apply workspace`

If `default-dataset` remains checked while another dataset is pending, the
default workspace stays visible until the new selection is applied.

Large transcriptome fixtures are intended for timing, queue, and workflow tests.
They should not slow down startup unless the user or admin explicitly selects
and applies them.

## Why this matters

This avoids a misleading state where the UI would appear to use one set of datasets while the backend is still operating on another.

## Typical workflow

1. open `Datasets`
2. check one or more authorized datasets
3. review the pending changes
4. click `Apply workspace`
5. move to `Dashboard` or `Query`

## Important rule

The workspace cannot be empty.

At least one dataset must remain selected.

:::tip
Use `Dashboard` immediately after applying a workspace if you want to confirm that the expected datasets, patients, and molecular files are really loaded.
:::

## When Apply workspace can fail

Applying a workspace requires every selected dataset to have a ready admin-built
DuckDB store. If a store is missing, stale, or failed, the user flow returns a
clear readiness message instead of rebuilding stores in the background.

Admins prepare or rebuild stores in `Data Administration`.

## Notes on permissions

Users only see datasets they are allowed to access.

Access can come from:

- dataset visibility
- matching group membership
- direct allowed-user assignment
