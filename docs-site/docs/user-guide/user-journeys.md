# User journeys

Select a task below. Use the bundled Synthetic longitudinal demo for clinical examples
and the [Synthetic cross-sectional demo](synthetic-cross-sectional-demo.md) for molecular
analyses. Apply your dataset selection before starting.

Prefer a demonstration? See the [video tutorials](../video-tutorials.md).

:::note[Synthetic examples]

The synthetic datasets test and demonstrate the app. Analysis results reflect
programmed patterns, not biological findings or clinical evidence. The autoimmune
demo has no treatment history or repeated visits; use the Synthetic longitudinal demo for
medication and longitudinal examples.

:::

## Journey 1: Find patients taking biologics

1. Open **Query** with **Workspace** selected.
2. Ask “Which patients take biologics?”
3. Check the matching patients and the filters used.
4. Choose **Save cohort** and name the group.

Medication-class questions may need an enabled LLM. For a first query without
one, ask “Which patients have Crohn Disease?”

![Query result using the Synthetic longitudinal demo](/img/screenshots/query-tab.png)

Use **Prompt scope: previous result** to refine a supported selection.
Otherwise, each question searches the workspace. Saving a paginated result
keeps all matching members, not only the visible page.

Missing treatment records do not mean that nobody takes a treatment.
The reply should identify missing data rather than report a false zero.

### Ask a general question

General questions use the model without attaching workspace data.

![Query context selector with General question selected](/img/screenshots/query-general-mode.png)

1. Select **General question** beside the Query input.
2. Ask “What is infliximab?” or “Erkläre kurz, was Infliximab ist.”
3. Read the model's answer.
4. Switch back to **Workspace** to ask about your datasets.

An enabled model is required. A General question cannot find patients or save
a cohort. You can also use this mode in Analysis.

<details>
<summary>See a completed answer from LM Studio</summary>

![LM Studio answering a general research question with no workspace context attached](/img/screenshots/query-llm-answer.png)

*The reply was generated by gpt-oss-20b; model wording can vary between runs.*

</details>

:::warning[Your question is sent to the model]

Workspace records are not attached, but the text you type and recent
general-question history are sent. Do not paste confidential information into
a request to an external provider. Check medical explanations against reliable
sources.

:::

See [Query](query.md) for result details, sorting, and exports.

## Journey 2: Learn more about the biologics subset

1. From the Query result, choose **Open in Analysis**.
2. Select **Describe my cohort** for a summary without an LLM.
3. Inspect counts and missing fields.
4. Open **Cohorts → Members** to find an individual to inspect.

In **Dashboard → Patients**, search that patient's ID or ClarID. Review linked
samples and assays, then open the patient's timeline.

![Clinical dashboard with synthetic data](/img/screenshots/workspace-shell.png)

Dashboard does not automatically inherit a Query subset. Its summaries describe
the active workspace.

### Find patients with several data types

Open **Dashboard → Multimodal**, select the required types, then inspect
**Matching patients**.

- **At least these types** allows additional data.
- **Only these types** excludes additional non-clinical types.
- Clinical records are required only when Clinical is selected.

Choose **Save cohort** to keep the matching patients. Their source datasets
remain attached; matching IDs from different datasets stay separate.

:::note[Coverage is not quality control]

Available modalities do not prove that specimens or visits match. Check
sample links and **Coverage limitations**. A missing assay in this view does
not establish that it was never performed.

:::

See [Dashboard](dashboard.md) for Timeline, Assays, and Imaging.

## Journey 3: Compare two medication cohorts clinically

Use a dataset with treatment records and repeated measurements.

1. In Query, find patients with Crohn Disease who take Infliximab.
2. Save the result as a cohort.
3. Find and save patients with Crohn Disease who do not take Infliximab.
4. Open Analysis and attach the groups as **Cohort A** and **Cohort B**.
5. Choose a clinical comparison method and complete **Inputs**.
6. Review the usable observations, run, and inspect the results.

For trajectories, select a numeric **Clinical measurement** with repeated dated
values in both groups. For Kaplan–Meier, also specify the event threshold and
review timing assumptions. The example marker in a prompt does not substitute
for selecting an available measurement.

![Analysis method and input setup](/img/screenshots/analysis-tab.png)

Read exclusions, sample counts, and method notes before interpreting the plot.
Expand **Result files** for tables and parameters. An optional LLM explanation
does not replace review of those outputs.

:::warning[Differences are not treatment effects]

Treatment groups may differ in disease severity, treatment selection, or other
factors. A plot alone does not establish that treatment caused the difference.

:::

See [clinical measurement requirements](analysis.md#clinical-measurement-selection).

## Journey 4: Explore transcriptomics differences between two groups

Load only **Synthetic cross-sectional demo**.

1. In Query, find and save patients with Systemic Lupus Erythematosus.
2. Save a healthy-control cohort.
3. In Analysis, select **limma-voom** and attach the two cohorts.
4. Select the synthetic RNA assay.
5. Check matched samples in both groups, review, and run.
6. Inspect the tested genes, effect sizes, adjusted p-values, and result files.

This demo uses fractional expected-count-like values. It is not suitable for
DESeq2's raw-integer-count input requirement. Assay sample counts may differ
from patient counts.

### Follow up across modalities

Choose **Associate two measurements** and turn A/B comparison off.
Use an example button, or select:

- Flow cytometry: `CD4_T_cells_fraction`
- Serology: `CRP_mg_L`

Review the feature descriptions and units, then run. Inspect the scatter plot,
overall and within-disease correlations, and excluded observations.

This compares two measurements; it is not an integration model for all assays.
See [matching rules and limits](analysis.md#compare-two-measurements).

<details>
<summary>Try a custom Python or R script</summary>

The [custom-script prototype](analysis.md#custom-python--r-scripts-synthetic-prototype)
requires a configured Docker sandbox and the unchanged bundled autoimmune demo.
Restricted datasets are not accepted.

Choose a language. Paste existing code, or generate a data-aware template and
check package versions and matched sample counts before sending it to a coding
assistant. Review returned code before running it. The template describes the
inputs; it does not validate the analysis.

</details>

## Journey 5: Use Pheno-Ranker and reuse selected samples

1. Open **Pheno-Ranker**.
2. Choose **Cohort comparison**, using the workspace or a saved cohort.
3. Check the setup summary and run.
4. Inspect the heatmap, MDS plot, and network when enabled.
5. Select records in a plot and choose **Save cohort** or **Open in Analysis**.

![Pheno-Ranker mode selection and run controls](/img/screenshots/pheno-tab.png)

For one target, choose **Patient ranking** and select a patient or visit from
the search field. You do not need to write a prompt.

**Explain results** shows computed evidence. **Explain with LLM** requests a
short model interpretation. Check either against the scores and shared or
differing features.

<details>
<summary>Optional UMAP projection</summary>

Enable **Render UMAP** in Settings before a new cohort run. It requires the
optional dependencies and at least three records. UMAP selections can also be
saved or opened in Analysis. Distances between displayed clusters are not the
original phenotypic distances.

</details>

:::note[Keep the selected records]

Use the app's transfer actions to retain sample and dataset identities.
Do not strip prefixes or merge matching source IDs manually. A selected cluster
is an exploratory group, not a validated disease subtype.

:::

See [Pheno-Ranker](pheno-ranker.md) for metrics, plots, and saved results.

## Export, organize and return later

Open **Cohorts** to find a saved group, inspect members, rename it, or export data.

| Export | Includes |
| --- | --- |
| Membership | Saved IDs and cohort metadata |
| Clinical | Current clinical records for saved patients, including all visits |
| Molecular | Supported assay matrices and sample links |

Exports use current source data, not frozen inputs from an old run. They exclude
raw sequencing files and DICOM pixels. See [export details and limits](saved-cohorts-and-handoffs.md#rename-and-export-a-cohort).

Query, Analysis, and Pheno-Ranker chats save automatically. Use folders and pins
to organize them. **Load this chat’s datasets** restores its original selection
if it remains available and unchanged. Rerun a restored Query before using
table exports or cohort actions.

Deleting a chat keeps generated runs and files; cleanup is separate in Settings.
**Save project** creates a same-installation resume file, not a data bundle or
backup. Protect it like other research exports.

## Settings and software versions

In **Settings**, change the theme or supported plot palettes. These affect
interactive charts, not existing R-generated images or the separate OHIF viewer.

Background-run notifications appear while the app is open; they are not email
or operating-system notifications. Keep Desktop open until jobs finish.

Use **Settings → About COHORTome → Copy version report** when reporting a
problem. It includes detected versions, not patient data or configuration.
On Web it describes the server, not separate workers or imaging services.
